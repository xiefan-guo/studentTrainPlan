# 学生培养计划管理系统 - 代码分析报告

---

## 一、项目概述

本项目是一个基于Flask框架开发的学生培养计划管理系统，面向高校学生和教育管理者，提供培养计划可视化管理、个性化课程推荐、课程论坛交流等功能。系统采用经典的Web MVC架构，实现了学生选课进度跟踪、基于协同过滤的课程推荐、论坛讨论等核心功能。技术栈包括：后端使用Python Flask框架配合PyMySQL进行数据库操作，前端采用jQuery + Bootstrap框架，可视化使用ECharts实现树状图和柱状图展示，推荐算法基于SVD奇异值分解实现。项目结构清晰，包含main.py路由文件、config.py配置文件、utils工具模块（数据库查询、推荐算法、数据映射）、templates前端模板、static静态资源和sql数据库脚本。

## 二、架构设计分析

### 2.1 系统架构评估

#### 架构描述

系统采用经典的**三层架构**模式：

```
┌─────────────────────────────────────────────────────────┐
│                    表示层 (View)                         │
│  HTML模板 + jQuery + Bootstrap + ECharts                │
├─────────────────────────────────────────────────────────┤
│                    业务逻辑层 (Controller)               │
│  main.py (Flask路由)                                    │
├─────────────────────────────────────────────────────────┤
│                    数据访问层 (Model)                    │
│  utils/query.py + MySQL数据库                           │
└─────────────────────────────────────────────────────────┘
```

#### 架构评估

**优点：**
- 结构清晰，分层明确，便于理解
- Flask框架轻量级，适合中小型项目快速开发
- 前后端分离程度适中，便于维护

**问题：**
- **缺少Service层**：业务逻辑直接写在路由函数中，违反单一职责原则
- **无依赖注入**：数据库连接硬编码在query.py中
- **配置管理不完善**：敏感信息（数据库密码）直接写在代码中
- **缺少API版本管理**：不利于后续接口升级

### 2.2 模块划分合理性

#### 各模块职责分析

| 模块 | 职责 | 清晰度 | 问题 |

3. **引入蓝图(Blueprint)**：按功能模块拆分路由

### 3.2 SVD推荐算法模块

#### 算法流程

```
评分矩阵构建 → SVD分解 → 特征提取 → 相似度计算 → 推荐生成
```

#### 数学原理

SVD（奇异值分解）将评分矩阵 $R$ 分解为：
$$R = U \Sigma V^T$$

其中：
- $U$：用户特征矩阵
- $\Sigma$：奇异值对角矩阵
- $V^T$：物品特征矩阵

通过保留前$k$个奇异值（保留90%能量），实现降维和噪声过滤。

#### 核心代码分析（recommed_module.py）

```python
def svdMethod(svdData, dataMat, simMeas, user, item):
    # 保留90%能量的特征值
    k = 0
    while sum(Sigma[:k]) < sum(Sigma) * 0.9:
        k = k + 1
    # 计算物品特征向量
    itemFeature = dataMat.T * U[:,:k] * SigK.I
    # 基于相似度计算预测评分
    for j in range(N):
        sim = simMeas(itemFeature[item,:].T, itemFeature[j,:].T)
        ratSim = dataMat[user, j] * sim
```

#### 效果评估

| 指标 | 评估 |
|------|------|
| 推荐准确性 | 中等（受数据规模限制） |
| 算法复杂度 | $O(mn^2)$，适合小规模数据 |
| 扩展性 | 较差，无增量更新机制 |

#### 性能分析

- **矩阵规模**：30学生 × 118课程
- **SVD分解**：约$O(30 \times 118^2) \approx 4 \times 10^5$次运算
- **性能瓶颈**：每次请求都重新计算SVD

#### 改进建议

1. **缓存SVD结果**：预计算并缓存分解结果
2. **使用增量SVD**：支持新用户加入
3. **考虑使用Surprise库**：更完善的推荐系统框架

### 3.3 课程论坛模块

#### 实现逻辑

论坛模块采用简单的**话题-回复**模式：

```
发布话题 → NEWS表存储(IS_FIRST='0') → 列表展示
发表回复 → NEWS表存储(IS_FIRST=话题ID) → 详情页展示
```

#### 数据结构

```
NEWS表:
├── TOPIC: 话题标题
├── COMMENTS: 内容
├── COMMENTER: 评论者
├── CREATE_TIME: 创建时间
├── NEWS_ID: 唯一标识
└── IS_FIRST: '0'表示话题，其他表示回复所属话题ID
```

#### 存在问题

1. **表设计不合理**：话题和回复混在同一张表
2. **缺少分页**：一次性加载所有数据
3. **无权限控制**：任何人可删除/修改他人内容
4. **XSS风险**：未对用户输入进行转义

## 五、安全性评估报告

### 5.1 SQL注入风险

#### 风险等级：🔴 **严重**

#### 风险点位置

系统中**所有SQL语句**都使用字符串拼接，存在严重SQL注入风险：

**main.py第42行**
```python
sql="INSERT INTO STUDENT VALUES ('%s','%s','%s','%s','%s','%s','%s','%s')" % (name,sex,stu_no,...)
```

**main.py第92行**
```python
sql = "select * from STUDENT where STU_NO = '%s'" % stu_id
```

**main.py第160行**
```python
sql = "INSERT INTO NEWS(TOPIC, COMMENTS, COMMENTER, NEWS_ID, IS_FIRST) VALUES ('%s', '%s', '%s', '%s', '0')" % (topic, comments, stu_name, news_id)
```

#### 验证示例

攻击者可通过以下方式注入：
```
学号: admin' OR '1'='1
密码: anything
```

#### 修复建议

```python
# 使用参数化查询
def query_safe(sql, params):
    db = pymysql.connect(...)
    cur = db.cursor()
    cur.execute(sql, params)  # 参数化查询
    return cur.fetchall()

# 使用示例
sql = "SELECT * FROM STUDENT WHERE STU_NO = %s"
result = query_safe(sql, (stu_id,))
```

### 5.2 其他安全风险

#### 🔴 密码安全

**问题**：密码明文存储

**位置**：main.py第127行
```python
if result[0][6] == password:  # 直接比较明文密码
```

```python
from werkzeug.security import generate_password_hash, check_password_hash
```

## 六、性能分析报告

### 6.1 后端性能瓶颈

#### 数据库连接管理

**问题**：每次请求都创建新连接

**位置**：query.py第7行
```python
def query(sql):
    db = pymysql.connect(...)  # 每次创建新连接
    cur = db.cursor()
    # ...
```

**影响**：
- 连接创建开销大（约10-50ms/次）
- 高并发时可能耗尽连接资源

**修复建议**：
```python
# 使用连接池
from dbutils.pooled_db import PooledDB

db_pool = PooledDB(
    creator=pymysql,
    maxconnections=20,
    host='localhost',
    user='root',
    password='***',
    database='studentTrainPlan'
)

def get_connection():
    return db_pool.connection()
```

#### 查询优化

**问题**：N+1查询问题

**位置**：map_student_course.py第30行
```python
for i in range(30):
    sql="SELECT COMMENT FROM CHOOSE WHERE STU_NO='%s'" % (stu_no)
    score = query(sql)  # 循环中执行30次查询
```

**修复建议**：
```python
# 一次查询获取所有数据
sql = "SELECT STU_NO, COMMENT FROM CHOOSE WHERE STU_NO IN (...)"
all_scores = query(sql)
```

#### 算法性能

**SVD算法性能分析**：

| 操作 | 时间复杂度 | 实际耗时（估算） |
|------|-----------|-----------------|
| 矩阵构建 | O(mn) | ~1ms |
| SVD分解 | O(mn²) | ~100ms |
| 相似度计算 | O(n²) | ~50ms |
| **总计** | - | **~150ms** |

**优化建议**：
- 预计算SVD结果并缓存
- 使用增量更新算法
